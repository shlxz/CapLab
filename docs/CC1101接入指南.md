# Cap CC1101 上手（Cardputer-Adv）

SKU: U219 ｜ 官方文档：https://docs.m5stack.com/zh_CN/cap/Cap_CC1101

---

## 0. 这块卡是什么

不是裸 CC1101 模块，是一整块卡带，插在 ADV 背面的 EXT 2.54-14P 上，两颗芯片：

| 芯片 | 能力 |
|---|---|
| **TI CC1101** | Sub-1GHz 收发，315 / 433 / 868 / 915 MHz，+10dBm，灵敏度 -99.5dBm，标称 440m |
| **ST25R3916** | NFC 前端，13.56MHz，ISO14443A/B、FeliCa、ISO15693，读距约 45mm，**支持卡模拟（NFC-A / NFC-F）** |

附件：315MHz、433MHz、868MHz（兼 915）三根 RP-SMA 橡胶天线。
板载 DC-DC 降压，自带一个 HY2.0-4P Grove 口（插上 Cap 后 Grove 照样能用）。

结论：**原来打算用 RC522 做的门禁/读卡，这卡直接覆盖了，还多了卡模拟。**

---

## 1. 引脚映射（官方，不可改）

Cap-Bus 14 脚，对应 ADV 的 EXT 14P：

| Cap Pin | 信号 | ADV GPIO | 说明 |
|---|---|---|---|
| 1 | CC1101_G0 (GDO0) | **G15** | 数据/中断，接收必需 |
| 2 | CC1101_RF_SW0 | **G13** | 频段选择，主机直接控制 |
| 3 | SCL | G9 | Grove 直通 |
| 4 | SDA | G8 | Grove 直通 |
| 5 | 5V_OUT | 5V | |
| 6 | GND | GND | |
| 7 | 5V_IN | 5V | 卡带供电输入 |
| 8 | **POWER_EN** | **G3** | 整块卡 3.3V 电源使能 |
| 9 | NFC_IRQ | **G4** | ST25R3916 中断 |
| 10 | NFC_CS | **G6** | NFC 片选 |
| 11 | SPI_SCLK | G40 | 与 SD 卡共用 |
| 12 | SPI_MOSI | G14 | 与 SD 卡共用 |
| 13 | SPI_MISO | G39 | 与 SD 卡共用 |
| 14 | CC1101_CS | **G5** | CC1101 片选 |

**三个必须记住的点：**

1. **Pin 8 POWER_EN = G3 必须由你拉高**，否则整块卡不通电，SPI 上一个字节都读不到。
2. **Pin 1/2 同时是 UART_TX/RX**，如果你还要接串口设备，这两个脚不能兼用。
3. **CC1101 只占 G5 做片选**，SD 卡是 G12，可以共存。SPI 三线（G40/G14/G39）三家共用。

## 2. 上电顺序（顺序错了会白折腾）

```
1. 关机（侧面电源开关 OFF）
2. 插 Cap（对准 EXT 14P，M2×4mm 螺丝固定，别用更长的，会顶穿内部 PCB）
3. 拧上对应频段的天线
4. 开机
```

**禁止热插拔。** 官方明确写了带电插拔可能导致设备异常。换天线、换卡一律先关机。

天线必须匹配当前频段，接错频段等于全反射，功率出不去还伤 PA。

## 3. 频段切换：两根控制线，只有一根在主机上

| RF_SW0 | RF_SW1 | 频段 | 该插哪根天线 |
|---|---|---|---|
| 0 | 0 | 315 MHz | 315 |
| 0 | 1 | 433 MHz | 433 |
| 1 | 1 | 868 / 915 MHz | 868 |
| 1 | 0 | **未定义，别用** | — |

- **RF_SW0** 是主机引脚 G13，直接 `digitalWrite`
- **RF_SW1 不在主机引脚上**，它接的是 CC1101 自己的 **GDO2**，只能通过 SPI 写 `IOCFG2` 寄存器，把 GDO2 设成静态电平输出

这就是这块卡最容易卡住的地方：你以为切频段是 `digitalWrite` 两下，实际有一根得钻进芯片寄存器里配。

## 4. 代码 A：Sub-GHz 收发（RadioLib）

M5 官方指定的驱动库就是 **RadioLib**（github.com/jgromes/RadioLib）。

```cpp
#include <M5Cardputer.h>
#include <RadioLib.h>

#define PIN_POWER_EN  3
#define PIN_RF_SW0   13
#define PIN_CC_CS     5
#define PIN_GDO0     15

#define FREQ_MHZ    433.0f

Module ccModule(PIN_CC_CS, PIN_GDO0, RADIOLIB_NC, RADIOLIB_NC);
CC1101 radio(&ccModule);

// 频段切换：RF_SW0 走 GPIO，RF_SW1 走 CC1101 的 GDO2 寄存器
void setRfBand(float mhz) {
  uint8_t rf_sw0, rf_sw1;
  if (mhz < 350.0f)       { rf_sw0 = 0; rf_sw1 = 0; }  // 315
  else if (mhz < 500.0f)  { rf_sw0 = 0; rf_sw1 = 1; }  // 433
  else                    { rf_sw0 = 1; rf_sw1 = 1; }  // 868/915

  pinMode(PIN_RF_SW0, OUTPUT);
  digitalWrite(PIN_RF_SW0, rf_sw0);

  uint8_t gdo2_cfg = RADIOLIB_CC1101_GDOX_HW_TO_0 |
                     (rf_sw1 ? RADIOLIB_CC1101_GDO2_INV : RADIOLIB_CC1101_GDO2_NORM);
  // 写 IOCFG2（0x0B）—— 具体调用以 M5 官方 Quick Start 为准，
  // RadioLib 版本不同常量名/接口可能不同
  radio.setGDO2Config(gdo2_cfg);
}

void setup() {
  auto cfg = M5.config();
  M5Cardputer.begin(cfg, true);
  Serial.begin(115200);
  delay(200);

  // 1. 先给卡带上电
  pinMode(PIN_POWER_EN, OUTPUT);
  digitalWrite(PIN_POWER_EN, HIGH);
  delay(100);              // DC-DC 稳定，别省

  // 2. 切频段（必须在 radio.begin 前后都保证 GDO2 已配好）
  setRfBand(FREQ_MHZ);

  // 3. 初始化 CC1101：频率, 码率, 频偏, 接收带宽, 功率, 前导码长度
  int st = radio.begin(FREQ_MHZ, 4.8, 5.0, 58.0, 10, 16);
  if (st != RADIOLIB_ERR_NONE) {
    Serial.printf("CC1101 init failed: %d\n", st);
    M5Cardputer.Display.printf("init fail %d", st);
    while (true) delay(1000);
  }
  Serial.println("CC1101 OK");
  radio.startReceive();
}

void loop() {
  M5Cardputer.update();
  String s;
  int len = radio.available();
  if (len > 0) {
    int st = radio.readData(s);
    if (st == RADIOLIB_ERR_NONE) {
      Serial.printf("RX [%d] %s  RSSI %.1f\n", len, s.c_str(), radio.getRSSI());
    }
  }
  if (M5Cardputer.Keyboard.isKeyPressed('t')) {
    radio.startTransmit("hello from cardputer");
    delay(100);
    radio.finishTransmit();
    radio.startReceive();
  }
}
```

**说明**

- `RADIO_SW1` 那行走的是 RadioLib 的 GDO2 配置常量，官方 Quick Start 里也是这个思路。若你的 RadioLib 版本没有 `setGDO2Config`，去 https://docs.m5stack.com/en/arduino/projects/cap/cap_cc1101 抄官方那段 `setRfBand()`，逻辑一模一样。
- 只做 433 也**仍然要设 RF_SW1=1**，所以跳过这一步 = 收不到任何东西。
- 想抓 433 遥控器的 OOK 码，普通 packet 模式抓不全，需要 Asynchronous 串行模式（RadioLib 的 `SX126x` 那套思路不适用，CC1101 要配 IOCFG0 输出原始解调波形），这一步建议先用 Bruce 或 Flipper 的 .sub 思路对照。

## 5. 代码 B：NFC 读卡

官方库：`m5stack/M5Unit-NFC`（配套 M5UnitUnified 框架）

```cpp
#include <M5Cardputer.h>
#include <M5UnitUnified.h>
#include <M5UnitUnifiedNFC.h>

using namespace m5::nfc::a;
using namespace m5::nfc::a::mifare::classic;

m5::unit::UnitUnified Units;
m5::unit::CapCC1101NFC unit{};
m5::nfc::NFCLayerA nfc_a{unit};
constexpr Key keyA = DEFAULT_KEY;   // 0xFFFFFFFFFFFF

bool ready = false;

void setup() {
  auto cfg = M5.config();
  M5Cardputer.begin(cfg, true);
  Serial.begin(115200);

  // 卡带上电
  pinMode(3, OUTPUT);
  digitalWrite(3, HIGH);
  delay(100);

  // 注意：SPI mode 1, 10MHz —— 和 CC1101 的 mode 0 不一样
  ready = m5::unit::wiring::addSPI(Units, unit, 10000000, 1) && Units.begin();
  Serial.println(ready ? "NFC OK" : "NFC not found");
}

void loop() {
  M5Cardputer.update();
  if (!ready) return;
  Units.update();

  if (M5Cardputer.Keyboard.isKeyPressed(' ')) {
    if (nfc_a.detect()) {
      Serial.printf("UID: %s\n", nfc_a.picc().uidAsString().c_str());
      Serial.printf("Type: %s\n", nfc_a.picc().typeAsString().c_str());
    }
  }
}
```

**注意**：`addSPI()` 会自己按主机型号映射引脚（ADV 上是 SCK=40 / MOSI=14 / MISO=39 / NFC_CS=6 / NFC_IRQ=4），不用手填。

## 6. 两者共存时的坑

| 组合 | 能不能同时 | 原因 |
|---|---|---|
| CC1101 + NFC | ⚠ 要切 SPI 模式 | 同一组线，CC1101 用 mode 0，NFC 用 mode 1，每次事务前重新 `beginTransaction` |
| CC1101 + microSD | ✅ | 不同 CS（G5 vs G12） |
| NFC + microSD | ⚠ | 同总线，注意 CS |
| 射频层面互相干扰 | ✅ 无 | 13.56MHz 和 315-915MHz 差得远，天线也分开 |
| 卡带断电时用任何功能 | ❌ | POWER_EN 低 = 整卡掉电 |

务实建议：**别同时跑 CC1101 和 NFC**，按功能分程序。两块功能都塞一个固件里，SPI 模式切换是主要 bug 来源。

## 7. Bruce 为什么用不了这块卡

Bruce 的 CC1101 引脚配置只有这几项：

```json
{ "sck": 40, "miso": 39, "mosi": 14, "cs": 5, "io0": 15, "io2": -1 }
```

它能设 CS 和 GDO0，但：

- **没有 POWER_EN 项** → G3 不会被拉高 → 整卡不通电
- **没有 RF_SW0 项** → G13 不会被驱动
- **没有 RF_SW1 通路** → GDO2 寄存器不会被配置

三个都缺。所以插上 Cap 进 Bruce 的 RF 菜单，大概率直接 `CC1101 not found`。

Bruce 官方 wiki 里 Cardputer 家族的默认值是给**裸模块走 Grove 口**用的（CS=G1, GDO0=G2），跟这块卡完全对不上。

想要开箱即用的 Sub-GHz 图形界面，得等 Bruce 加 Cap 支持，或者自己写。现阶段就老老实实用 Arduino + RadioLib。

## 8. 故障排查

| 现象 | 原因 |
|---|---|
| SPI 完全没反应，读不到版本号 | POWER_EN（G3）没拉高，或拉高后没延时 |
| 能初始化但收不到任何信号 | RF_SW1 没配（433 需要 sw1=1）；或天线频段不对 |
| 只有近距离能收到 | 天线没拧紧 / 插错频段天线 / 金属遮挡 |
| NFC 找不到卡 | SPI mode 用成 0 了，必须 mode 1 |
| 换了频段就失效 | 忘了同步换天线，也忘了改 RF_SW0 |
| 上电异常重启 | 插拔时没关机，或螺丝过长顶到内部 PCB |

## 9. 下一步能做什么

1. **433 遥控器抓码重放**：家里卷帘门/门铃，抓 OOK 波形
2. **门禁卡读写**：MIFARE Classic 读 UID，比 RC522 稳
3. **卡模拟**：NFC-A/F 模拟，做个可编程的门禁卡沙盒（这块卡的核心卖点，社区还没人做）
4. **868 段传感器嗅探**：欧洲标准的温湿度传感器、水表气表都在这个段
5. **Grove 口还空着**：ENV III、Unit IR 照样能插
